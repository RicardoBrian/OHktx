# OHktx

개인용 코레일(KTX) 취소표 감시 + 반자동 예매 웹앱.

원하는 구간/날짜/시간대를 등록해두면 주기적으로 좌석을 확인하고,
- **캡차(보안문자)가 뜨면** 예약/결제를 진행하지 않고 **알림만** 보냅니다.
- **캡차가 뜨지 않으면**, `자동결제` 옵션을 켠 watch에 한해 좌석 예약과 결제까지 자동으로 진행합니다.

## ⚠️ 먼저 읽어주세요

- **개인용입니다.** 본인 명의 코레일 계정으로, 본인이 탈 여정만 예매하는 용도로 설계했습니다. 타인에게 예매를 대행해주고 대가를 받는 서비스로 운영하는 것은 철도사업법상 부정판매(웃돈 거래)에 해당할 수 있습니다.
- **코레일 이용약관 위반 소지가 있습니다.** 매크로/자동화 예매는 계정 이용 제한(정지)의 사유가 될 수 있습니다. 감수하고 개인 책임 하에 사용하세요.
- **이 저장소의 코드는 실제 코레일 사이트에 대해 라이브로 검증되지 않았습니다.** 개발 환경의 네트워크 정책상 korail.com 접속이 차단되어 있어, `src/korail/selectors.ts`의 CSS 셀렉터들은 공개적으로 알려진 사이트 구조를 바탕으로 한 추정치입니다. 실제로 동작시키려면 아래 "셀렉터 검증" 절차가 반드시 필요합니다.
- 카드정보는 서버의 SQLite DB에 AES-256-GCM으로 암호화되어 저장되지만, 이 앱을 외부에 노출된 서버에 그대로 올리는 것은 권장하지 않습니다. **개인 PC나 홈서버, 신뢰하는 사설 네트워크에서만 구동하세요.**

## 아키텍처

- Node.js + TypeScript + Express, SQLite(better-sqlite3), Playwright(Chromium)로 구성된 단일 프로세스 앱입니다.
- `src/korail/client.ts`가 Playwright로 코레일 웹사이트를 직접 조작합니다(로그인 → 열차 조회 → 예약 → 결제).
- `src/scheduler.ts`가 `POLL_INTERVAL_MS` 간격으로 활성화된 watch들을 순회하며 클라이언트를 호출합니다.
- 캡차 감지는 `KorailClient.hasCaptcha()`에서 페이지 내 "보안문자/captcha" 관련 키워드/엘리먼트 유무로 판단하는 휴리스틱입니다. 코레일이 캡차 UI를 바꾸면 `src/korail/selectors.ts`의 `captcha` 항목만 수정하면 됩니다.
- 알림은 텔레그램(선택) + 인앱 알림(웹 UI 하단 "알림/로그")으로 이중화되어 있습니다.

## 설치 및 실행

```bash
npm install
cp .env.example .env
# .env를 열어 아래 값들을 채우기
#   APP_PASSWORD, SESSION_SECRET, ENCRYPTION_KEY 는 필수
#   openssl rand -hex 32   ← SESSION_SECRET, ENCRYPTION_KEY 생성에 사용

npm run build
npm start
# http://localhost:3000 접속 후 APP_PASSWORD로 로그인
```

개발 중에는 `npm run dev`로 자동 재시작하며 작업할 수 있습니다.

Playwright가 요구하는 크로미움 버전과 시스템에 이미 설치된 버전이 다르다는 오류(`Executable doesn't exist ...`)가 나면:
- `npx playwright install chromium` 으로 새로 받거나,
- 이미 다른 경로에 크로미움이 있다면 `.env`의 `PLAYWRIGHT_CHROMIUM_PATH`에 그 실행파일 경로를 지정하세요.

## 셀렉터 검증 (실제 사이트에 맞게 고치는 법)

1. `.env`에서 `BROWSER_HEADLESS=false`로 설정하고 서버를 실행하면, watch를 확인할 때마다 실제 브라우저 창이 뜹니다.
2. 브라우저 개발자도구(F12)로 코레일 로그인 폼, 검색 결과 테이블, 결제 폼의 실제 DOM 구조(태그/속성/name)를 확인합니다.
3. `src/korail/selectors.ts` 안의 값만 실제 구조에 맞게 고칩니다. `src/korail/client.ts`의 로직은 셀렉터가 가리키는 요소가 존재하는 한 그대로 동작하도록 작성되어 있습니다.
4. 특히 `search.dateSelect`/`search.timeSelect`처럼 `<select>`를 다루는 부분은 실제 `<option value="...">` 포맷(예: `20260710` vs `2026-07-10`)에 맞춰 `client.ts`의 `selectOption` 인자를 조정해야 할 수 있습니다.

## 주요 화면/기능

- **로그인**: `.env`의 `APP_PASSWORD` 하나로 보호되는 단일 사용자 로그인.
- **설정 → 코레일 계정**: 로그인 아이디/비밀번호 (암호화 저장).
- **설정 → 결제수단**: 카드번호/유효기간/생년월일(또는 사업자번호)/카드비밀번호 앞 2자리 (암호화 저장). `자동결제`를 켠 watch가 없다면 등록하지 않아도 됩니다.
- **감시(watch) 추가**: 출발역/도착역/날짜/시간대/열차종류/좌석종류/인원, 그리고 "캡차 없으면 자동결제까지 진행" 체크박스.
- **감시 목록**: 상태(active/paused/completed) 확인, 일시정지/재개/삭제.
- **알림/로그**: 좌석 발견, 캡차로 인한 중단, 예약/결제 완료, 오류 등을 시간순으로 확인.

## 텔레그램 알림 설정 (선택)

1. 텔레그램에서 [@BotFather](https://t.me/BotFather)로 새 봇을 만들고 토큰을 받습니다.
2. 만든 봇과 대화를 시작한 뒤, `https://api.telegram.org/bot<토큰>/getUpdates`를 호출해 본인의 `chat.id`를 확인합니다.
3. `.env`의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`에 채워넣고 서버를 재시작합니다.
4. 설정하지 않아도 인앱 알림(웹 UI)은 항상 동작합니다.

## 알려진 한계 / TODO

- 코레일 사이트의 실제 DOM 구조를 이 개발 환경에서 검증하지 못했습니다 (네트워크 정책상 접근 불가). 최초 실행 시 반드시 위 "셀렉터 검증" 절차를 거쳐야 합니다.
- 캡차 감지는 키워드/셀렉터 휴리스틱이라 완벽하지 않습니다. 실제 이미지 캡차를 자동으로 푸는 기능은 의도적으로 구현하지 않았습니다(약관 위반 소지가 더 커짐).
- 좌석이 여러 개 검색되면 첫 번째 열차만 시도합니다.
- 연속 오류에 대한 자동 일시정지(circuit breaker)는 없습니다. 알림이 계속 온다면 웹 UI에서 직접 watch를 일시정지하세요.
- 코레일은 이미 "예약대기" 등록 시 취소표 발생 자동배정 기능을 공식 제공합니다. 순서를 기다릴 수 있다면 이 앱보다 그쪽이 더 간단하고 약관 문제도 없습니다.
